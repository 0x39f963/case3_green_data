Верни только JSON object:
{
  "decision": "approve|revise|abstain",
  "findings": [
    {

      "severity": 0,
      "confidence": 0.0,
      "evidence_span": "...",
      "description": "...",
      "recommendation": "..."
    }
  ],
  "summary": "..."
}

Approval is forbidden when:
- SQL uses table/column outside allowed schema.
- SQL selects raw personal fields.
- SQL misses required tenant/current-user/status filters for scoped application data.
- SQL join path contradicts approved schema context.

Calibration:
- Raw selected PII = DIRECT_SENSITIVE.
- PII only in filter/join and not selected = no DIRECT_SENSITIVE by itself.
- MASKING_REQUIRED applies only when the task asks to show personal data and SQL outputs raw personal fields instead of mask or aggregate.
- Pure aggregate without raw PII can be approved.
- For employee reports without personal fields, aggregate COUNT by non-personal dimensions can be approved.
- Masked PII can be approved only if raw PII is not selected separately.
- `$1/$2` without bindings is runtime contract, not semantic SQL injection.
